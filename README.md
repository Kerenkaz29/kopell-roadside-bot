# Kopell Roadside Bot

A WhatsApp bot that handles a roadside-assistance request end to end: it talks to the customer, figures out what happened to the car, gets their location, and dispatches the nearest available technician - with live status updates as the job progresses.

## How it works

1. Customer messages the business WhatsApp number.
2. The bot asks what happened, understands the free-text answer with AI (not keyword matching), and asks for the customer's location.
3. Once a location and vehicle/policy number are provided, it finds the nearest available technician (MongoDB geospatial query) and dispatches them.
4. The customer gets automatic status updates (on the way → arrived → completed), and can cancel the request at any point in natural language.
5. A live dashboard (`/admin/requests`) shows every open request, its status, and assigned technician.

Every customer-facing message is generated by AI at the moment it's needed (not a fixed template), so the conversation reads naturally while the underlying state machine stays simple and predictable.

## Stack

- **Node.js + Express** - webhook server
- **MongoDB** - conversations, requests, technicians (with `2dsphere` geo indexes for dispatch)
- **WhatsApp Cloud API (Meta)** and **Twilio** - both supported as messaging providers
- **Gemini** - issue classification, vehicle/policy extraction, cancel-intent detection, and all reply generation

## Project layout

```
src/
  server.js              Express app: webhook endpoints + admin dashboard
  stateMachine.js         Conversation flow (issue -> location -> vehicle -> dispatch)
  dispatch.js             Finds the nearest available technician and computes ETA
  statusSimulator.js      Advances a dispatched request through its lifecycle, pushing updates
  config.js               Env var loading
  seed.js                 Seeds mock technicians
  demo.js                 Scripted end-to-end run for live demos (no real WhatsApp needed)
  models/                 Mongoose schemas: Conversation, ServiceRequest, Technician
  whatsapp/
    metaClient.js          Sends messages via Meta's Graph API
    twilioClient.js        Sends messages via Twilio
    parseIncoming.js        Normalizes Meta's webhook payload
    parseIncomingTwilio.js  Normalizes Twilio's webhook payload
  ai/
    classifyIssue.js         Free text -> issue category + summary
    extractVehicleInfo.js    Free text -> vehicle number + policy number
    detectCancelIntent.js    Free text -> does the customer want to cancel?
    generateReply.js         Instruction + facts -> natural customer-facing message
    geminiClient.js          Thin wrapper around the Gemini API
```

## Setup

1. `npm install`
2. Copy `.env.example` to `.env` and fill in: a MongoDB URI, WhatsApp credentials (Meta and/or Twilio), and a `GEMINI_API_KEY`
3. `npm run seed` to create a handful of mock technicians
4. `npm start` (or `npm run dev` for auto-reload)
5. Expose the server publicly (e.g. `ngrok http 3000`) and point your WhatsApp provider's webhook at `/webhook` (Meta) or `/webhook/twilio` (Twilio)

## Trying it without a live WhatsApp connection

`npm run demo` walks a simulated customer through the whole flow (issue → location → vehicle → dispatch) by posting directly to the webhook endpoint, and prints the conversation state at each step. Open `/admin/requests` in a browser alongside it to watch the request appear and its status progress live.

## Docker

`docker compose up -d` builds and runs the app together with a MongoDB container (`restart: unless-stopped`, so it comes back up automatically whenever Docker starts). A publicly reachable tunnel (e.g. ngrok) is still needed separately for WhatsApp to reach the webhook.
